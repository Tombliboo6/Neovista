# 全局总管三层 Agent 架构

## 视频任务上下文（0.1.40）

项目检查器提供 `videoGeneration.selectedEngine`、配置ID及已有镜头的服务、模型、状态、阶段和任务编号。共用提示词不随生成方式切换而重新生成；选择项控制未来提交，已有任务按自身快照诊断。总管指令已区分本机H3、MiniMax与Seedance，接单不明时提示核实任务号，下载失败时只恢复原结果。实际提交和付费边界继续由已有界面操作及工作流审批控制。详见 `VIDEO_PROVIDER_ARCHITECTURE_2026-09-09.md`。

## 目标

让用户始终面对一个全局总管对话入口。总管能够读取整个项目，判断问题真正发生在哪个环节，绑定稳定项目实体，解释修改影响，并按顺序提出操作计划。所有真实改动和 Provider 调用仍遵守项目审批、版本、失败保留和显式提交规则。

## 三层职责

| 层级 | 职责 | 当前实现 |
| --- | --- | --- |
| L1 全局总管 | 理解用户意图，读取全项目状态，定位上游原因，制定跨环节计划，说明下游影响 | 已提供全项目快照、阶段诊断、稳定资产绑定、结构化操作计划和项目偏好读取 |
| L2 专业 Agent | 负责剧本、人物、场景、道具、分镜、视频提示词、音乐方案等专业产物 | 总管的白名单命令可在确认后调用现有角色、场景、道具、分镜图和视频提示词流程 |
| L3 执行与 Provider | 保存版本、审批、任务队列、图片生成、H3、音乐与本地合成 | 继续复用原工作流和 Provider 适配器；生成类命令必须由用户明确确认 |

## 当前总管：白名单命令执行

当前版本使用以下链路：

1. 用户在左侧“全局总管”中明确发送问题。
2. 前端先保存当前项目，服务端读取同一项目的版本化工作流快照。
3. 项目检查器汇总15个阶段、问题、恢复动作和稳定资产 ID。
4. 文字 Agent 返回诊断、目标阶段、目标资产、建议操作顺序和下游影响。
5. 程序再次约束返回值：不存在的资产被剔除，影响范围只能来自真实依赖图，只生成已实现的白名单命令。
6. 用户本轮明确说“修改”、“修复”或“写入”时，文字类命令立即进入运行态；界面显示目标、进度、完成或失败结果。
7. 对话、命令和结构化诊断随项目持久化。

总管不开放任意路由或任意代码执行。文字分镜修复只写入通过完整校验的文字分镜，不批准后续阶段，不删除旧结果，也不顺带提交图片、视频、音乐或 H3 任务。

## 第二阶段：带审批的命令计划

当前实现把总管建议编译为程序白名单命令：

1. 服务端只接受真实项目快照中的稳定实体，无法唯一绑定的建议不会产生执行按钮。
2. 导航命令不调用 Provider；生成图片、编辑图片和生成视频提示词均显示 Provider 影响并等待用户点击“确认执行”。
3. 确认后仍调用原有阶段处理函数、依赖门和 Provider 适配器，不开放任意路由或任意代码执行。
4. 命令状态、结果说明和失败原因随项目对话持久化；失败不会自动重试或更换参数。
5. “记住偏好”只在用户明确表达长期偏好时出现，确认后只写入当前项目，最多保留50条，并作为后续总管上下文。

## 第三阶段：可恢复的跨环节协作

- 由总管跟踪命令状态和部分结果，失败时解释真实原因并提供恢复选项。
- 任何重试、改参或 Provider 切换都形成新的显式命令，不静默发生。
- 上游修改只标记下游 `stale`，旧资产、错误、参数、任务编号和审批记录继续保留。
- 总管可帮助用户修改任一环节，但每次修改仍落在稳定实体、版本和审批边界内。

## 核心代码

- `src/manager/project-inspector.ts`：只读项目上下文与检查工具。
- `src/manager/global-manager.ts`：总管对话契约、结构化输出和安全归一化。
- `src/manager/manager-commands.ts`：稳定实体绑定、白名单命令编译和 Provider 影响约束。
- `web/local-api.mjs`：读取当前保存项目并发起一次文字分析。
- `web/src/App.tsx`：总管对话、诊断计划展示和项目级持久化。
