# 技术架构基线

## 三种视频生成接口（0.1.40）

导演模式与自由画布复用中文提示词，在提交时选择本机 H3、MiniMax 海螺或 Seedance API。云协议位于 `src/providers/cloud-video.mjs`，`web/video-jobs.mjs` 保存一次提交意图、原配置版本、远端 ID、状态及本地结果；未知接单不重提。结果经解码后进入待验收并接回播放器及剪辑。明确无声的云镜头粗剪使用等长静音轨，缺少所请求音轨时阻断。实际能力、恢复及验收边界见 `VIDEO_PROVIDER_ARCHITECTURE_2026-09-09.md`。

## 视频提示词引用与编译（2026-09-09）

单段、批量及修复 Agent 共用 `VIDEO_PROMPT_PRODUCTION_POLICY`。中文五段式定义一次来源关系，在主体出场、切镜及动作归属需要时使用稳定标签；结构化画格与时间由 `withStoryboardVideoGuide` 编译为集中参考说明。`videoReferenceIssues` 同时用于生成结果与 H3 提交前，检查标签、来源配对、主体使用以及画格顺序和时间覆盖，支持集中和已有逐段映射。正文与参考说明冲突时保留草稿并返回诊断。详见 `STUDIO_VIDEO_REFERENCE_POLICY_2026-09-09.md`。

## 故事板视觉参考（0.1.30）

视频提示词通过 `AgentRequest.images` 传输当前分段的整张故事板，图片附件带稳定分段 ID，图片字节独立于文本 JSON。Responses 使用 `input_image`，Chat Completions 与 Anthropic 由 AI SDK 转换图片内容块。批量输入与单段修复保留各自图片绑定；读取失败在模型调用前返回，接口不支持图片时保留原始错误。

H3 Ref2VA 使用与视频提示词一致的参考顺序：人物、场景、道具，然后整张故事板。`referenceLayoutVersion: 2` 与 `storyboardReference` 保存实际图、宫格数与 `<Picture N>`；`storyboardVisionVersion: 1` 表示本次提示词请求携带了图片，不代表生成质量验收。旧项目把原来位于首项的故事板移动到资产之后，保留正文资产编号。提交包含画格与时间线的参考说明，故事板作为分镜引导。图片变化仅使对应下游过期，媒体仍保留。

## 严格结构化请求（0.1.28）

`strict-output-schema.ts` 在 Responses 发送前检查严格 JSON Schema 的对象必填字段、封闭对象、数组元素和枚举，并按 Schema 节点转换传输约束。结构缺陷以 `invalid_local_json_schema`、字段路径和零请求次数返回；领域 Schema 不被改写。故事板逐段失败将原始错误保存到 `private/agent-diagnostics`，诊断编号随该段错误返回；汇总消息只描述实际失败阶段。

## Responses 文字流式接收（0.1.27）

`src/providers/openai-responses.ts` 发起 Responses 流式请求，`responses-stream.ts` 负责受大小限制的 SSE/UTF-8 解码、事件分派、完成判定与断流诊断。完成事件仍经过现有模型匹配、JSON Schema 和领域校验。前端继续接收完整业务对象。只有已有的请求前 HTTP 临时故障策略允许有限重试，流式读取失败不会重新生成；同次响应为 JSON 时直接使用原校验路径。

智能拆集由 `web/local-api.mjs` 设置 300000 毫秒请求上限；错误通过本地 API 保存至数据目录 `private/agent-diagnostics/`，制作任务同时保留其调用诊断。该目录用于本地支持排查，正文片段不能作为已完成项目结果。模型检测通过 `model-health.ts` 验证模型元数据，区分有效信息、模型缺失和无效响应。

## 模块边界

- `domain`：不依赖网络、SDK、数据库驱动或UI。
- `workflow`：只处理阶段依赖、审批、失效传播和任务编排。
- `providers`：隔离第三方API与本地H3协议。
- `storage`：后续提供SQLite持久化、媒体索引和版本关系。
- `workers`：后续负责队列、超时、取消、媒体验证和合成。

## 关键状态规则

- 剧本批准后先生成文字人物介绍；人物介绍通过后才允许记录用户的画风选择。
- AI只能给出画风候选与推荐理由，最终 `StyleSelection` 必须由用户选择并按精确版本批准。
- 人物主资产提示词采用“程序固定结构 + Agent生成可变设计”：程序拥有中文五段式标题、横版3:2“左侧面部近景 + 右侧完整全身”双栏版式、完整预设画风锚点注入和校验规则；Agent结合当前角色补全人物视觉设计，并扩写材质、光影、色彩与成像内容。生产提示词不得包含外部产品、平台或品牌来源表达。
- 人物主资产使用可复用的干净基础定妆，不固化雨湿、泥渍、中毒、血迹、战损或能力激活等临时状态。经已批准人物事实支持的一件代表性道具可仅出现在右侧主全身图，但不作为人物身份锚点，后续仍建立独立道具资产。
- 详细三视图不与首张主资产合并生成。用户在画布上批准主资产后，可点击“生成详细三视图”，以已批准主资产图作为唯一身份与服装参考，生成正面、严格左侧面和完整背面派生资产。
- 详细三视图使用程序固定的中文五段式提示词模板，不再调用文字Agent；提示词不依赖人物名或画风名，人物身份、服装与画风只由当前上传的唯一主资产参考图控制。模板固定三格布局、空手中性站姿、正交机位、统一比例及最高风险负面词，避免二次创作人物设定。
- 三视图必须绑定主资产ID与精确版本；主资产修订后只将旧三视图标记为`stale`并保留。在Images参考图编辑接口未验证前，前端按钮必须显示不可用原因，不得降级为无参考文生图。
- 提示词集合保留稳定ID、版本和审批状态；修订生成新版本并回到`draft`，已批准提示词之前不得调用Images Provider生成正式人物资产。
- Images Provider默认使用`quality=high`；调用方仍可对明确的低成本预览任务覆盖质量。独立图片任务的初始队列并发为2，该值已通过同一Key/路由双请求受理实测；提高上限前仍须重新验证，失败后不得自动换Key、改参或重试。Provider必须检查返回媒体的实际尺寸，不能以请求参数代替结果验收。
- 图片队列的并发上限可配置，但产品默认只能使用已实测通过的值。更高并发必须先以独立无客户内容诊断任务验证，不与正式资产混测；首个失败后停止调度尚未提交的任务，已提交任务可自然结束，所有成功、失败和未启动状态均保留。
- 场景资产先由文字Agent基于已批准剧本和画风生成“视觉提案 + 场景主资产提示词”，再由用户按精确版本审批；未批准提示词不得调用Images Provider。
- 场景按物理地点而非场次机械拆分：同一地点的连续场次共用一个稳定`sceneAssetKey`。最早场次定义可复用主资产的基础状态，爆炸、坍塌、烧毁等后续状态作为带逐字剧本证据的派生变体记录，不提前固化进主资产。
- 场景逐字证据由程序管理：程序从已批准剧本建立逐场证据目录，文字Agent只选择对应场次的证据ID，程序回填原文后再校验。Agent负责地点归并、状态判断与视觉设计，不负责复制原文。
- 场景主资产默认是横版16:9纯环境空镜，固定前中后景、表演区、通行路径和至少三处空间地标；不混入人物、可移动剧情道具或后续状态。道具仍在独立阶段建立。
- 主场景图按精确版本批准后进入独立`scene-views`阶段：以该主场景图作为参考，生成反打、左右侧向和高位概览等可复用视角；每张派生图必须绑定主场景ID、版本和文件哈希，并保持地标身份、相对位置、道路轴线、天气与画风一致。
- 场景多视角要求已验证的参考图编辑能力；Provider不可用时阶段保持禁用并显示原因，不得降级为无参考文生图。主场景修订后旧多视角只标记为`stale`并保留。
- 道具文字阶段采用“程序管理剧本证据与固定资产板 + Agent补全视觉提案”：同义称谓先归并为一个稳定道具，基础形态与激活、损坏等状态变体分别保存，状态变体必须绑定对应场次逐字证据。
- 道具主资产固定为横版3:2单图：左侧大型三分之四主视图，右侧2×2展示正面、侧面、顶面和底面；所有视图必须为同一件未激活、未受损道具，不混入人物、手、剧情环境、能量特效或文字标签。
- 道具视觉提案与提示词集合按精确版本批准后才能进入Images Provider。激活或毁坏效果应作为绑定已批准基础资产的派生状态任务，不得反向污染基础主资产。
- 分镜文字阶段以可配置`segmentDurationSec`沿整集时间轴确定性建立固定槽位，默认15秒；除整集最后不足所选时长的余数段外，所有分段时长必须与用户选择完全一致。总导演兼分镜Agent根据剧情密度把完整场次按原顺序分配到槽位，同一场可连续占用多个槽位，但一个分段不跨场；场尾转场只落在分段边界。文字Agent只输出简洁卡片式分镜描述、结构化证据以及人物/场景视角/道具状态语义，不直接选择资产ID，也不重复生成完整五段式长提示词。
- 分镜返回后由程序把人物名映射到已批准人物主资产，把`sceneViewKey`映射到同地点的已批准主场景或多视角资产，把道具状态映射到已批准休眠/激活态资产；长资产ID只保存在后台结果中，不显示在用户卡片或要求用户选择。
- 文字分镜批准后，故事板可选择不生成、单图、四宫格、六宫格或九宫格，默认六宫格。文字Agent先输出带稳定画格顺序和连续时间范围的结构化规划，程序编译隐藏的五段式静态图提示词后直接提交生图；用户无需额外审批提示词，但可在图片详情查看。
- 宫格故事板与后续视频提示词共享同一份结构化画格规划；后续不得通过视觉模型重新分析故事板来反推顺序。当前段应出现的人物、人物状态、场景状态、道具和排除元素由文字Agent结合剧本证据、资产资料与前后分镜判断；本地程序只校验JSON结构、画格数量、连续时间范围和所引用批准资产是否存在，不使用本地关键词表冒充剧情理解。
- 宫格画面是连续时间中的叙事检查点，不机械等于独立镜头。每格必须携带连续`shotGroupKey`、与前格关系、具体切镜触发器、精确起止状态、行动单元、动作主体、动作摘要及阶段；同一镜头组内不得伪造切镜，新增镜头组必须命中明确触发器，4至6秒短镜头最多两个镜头组。
- 相邻画格必须把前格`endState`逐字传递为后格`startState`。同一行动单元只能连续出现，主体和摘要保持一致，最多完成一次；完成后只允许保持结果或进入下一个行动单元，不得在后续画格重新执行。
- 文字Agent在同一次返回中提供`semanticDecision`、逐格人物/道具语义、连续画格规划和五段式隐藏生图提示词，四者必须由请求明确要求相互一致。代表性道具只是人物资产资料的一部分，不自动等于当前分镜可见道具。
- 同一剧集其余故事板可由文字Agent一次批量规划，但返回仍是按分段稳定ID排序的独立计划；程序逐段执行与校验，单段失败不得污染或改写其他段。图片生成随后进入独立有界并发队列，而不是由文字调用直接触发生图。
- 分镜的智能决策仍由文字Agent完成；程序只固定整集时间窗、每段覆盖场次与时长，并验证动作/对白覆盖、逐字对白、角色、场景视角、道具状态和转场。详细图片生成控制留到分镜图任务阶段。
- 分镜校验区分硬错误与软警告：不可执行的结构、时长、对白、资产和道具因果错误阻断；动作证据ID顺序与去重由程序自动规范化，轻微覆盖差异写入`validationWarnings`后继续进入待审核。不得要求开发者为普通模型偏差逐次修改代码。
- 视频提示词保持一次点击完成两阶段：首轮按最多三段批量起草；只有未通过必要校验的分镜进入第二轮，每个`SEGxxx`携带原草稿、具体问题与证据独立交给文字Agent审校，最多四段并行。程序只负责调度、稳定ID和结果校验，不替Agent改写正文；第二轮仍失败时保留最新草稿且不再自动发起第三次调用。
- DeepSeek、Kimi、智谱GLM和通用OpenAI兼容文字接口由Vercel AI SDK统一发送`json_object`请求并在本地按领域Schema验收；Claude使用同一SDK的Anthropic Provider原生JSON Schema输出。SDK自动重试固定为0，错误继续保留HTTP状态、请求ID和安全诊断。OpenAI官方Responses协议保持独立适配器。
- 视频提示词时间线必须继承六宫格的镜头组、切镜原因、起止状态和行动单元，不允许视频Agent重新猜测镜头结构。一个时间段只能合并同一镜头组中的相邻画格，执行正文必须明确写出动作主体；旧六宫格缺少导演连续性字段时，在文字API调用前阻断并要求重新规划，旧结果仍保留。
- Images文生图与参考图编辑使用独立环境变量组：`IMAGE_API_*`与`IMAGE_EDIT_API_*`。即使两组指向同一网关，也必须由调用方显式选择，编辑通道的探测失败不得改变已验证文生图通道。
- 人物介绍与人物图片是两个独立阶段；人物介绍和画风任一未批准时，不得提交人物图片生成。
- 上游修改后，下游从 `ready` 变为 `stale`，旧资产继续保留。
- 逐阶段审批模式下，进入下一阶段前必须有匹配实体版本的审批记录。
- 全自动模式允许顺序运行，但失败后停止，不静默改参重试。
- Herrgotts续接请求分为本地依赖队列与H3实际队列：上一段尚未完成时只持久化`waiting_dependency`、紧邻来源段和当次参数，不向H3提交；来源段成功返回可续接元数据后才执行一次提交。来源段失败或取消时保持等待，用户可取消等待；不得自动重试来源段、改参或跨段续接。
- 视频完成必须检查 `prompt_id`/任务ID、实际输出文件、FFprobe信息和解码结果。
