## 执行与回滚

这是无 schema 迁移、无依赖变更的增量发布，不能把差异包交给全量 `rsync --delete`。

1. 重验线上原始文件摘要和就绪检查；存在在途或待复核任务则不开始切换。
2. 将被覆盖文件与原 Nginx 配置保存到只允许管理员访问的发布备份目录，记录新增路径，验证备份摘要。
3. 使用维护入口短暂拒绝新请求，等待现有请求收敛，再停止 API。
4. 原子替换两个后端文件，启动 API，确认本机 readiness 通过。
5. 安装全部新增资源，最后原子替换 HTML 入口，再恢复原 Nginx 配置。
6. 逐文件验证受管文件摘要，检查公开 readiness、模板与能力接口、未登录的预览鉴权；不提交付费任务。
7. 恢复公网前失败时，脚本确认维护入口生效后恢复原文件和入口、移除仅本次新增的文件、恢复原 Nginx 配置并启动旧 API。恢复公网后的外部验收若发现问题，须重新进入维护并确认无在途任务后才可回退；单纯审计记录写入失败不触发停服。数据库没有迁移，不执行数据库回退。

实际执行记录与摘要应存入发布备份目录；密钥、用户数据和签名结果 URL 不进入清单。
